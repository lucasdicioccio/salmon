# Builtins, recipes and binaries

## Builtin nodes


## Recipes

`salmon-ops-recipes/src/SreBox/` — opinionated compositions of the builtins above, where this project's own conventions get enforced:

```html
<table>
<tr><th>Module</th><th>Covers</th></tr>
<tr><td><code>CabalBuilding</code></td><td>building and publishing cabal-based binaries</td></tr>
<tr><td><code>DNSRegistration</code></td><td>DNS record registration</td></tr>
<tr><td><code>Environment</code></td><td>environment/machine bootstrapping</td></tr>
<tr><td><code>Initialize</code></td><td>initial setup sequencing</td></tr>
<tr><td><code>JWTSigning</code></td><td>JWT signing key management</td></tr>
<tr><td><code>MicroDNS</code></td><td>a minimal DNS server setup</td></tr>
<tr><td><code>PostgresInit</code></td><td>database/user/group/grant setup for a Postgres cluster (locally or driven onto a remote machine via <code>Self</code>)</td></tr>
<tr><td><code>PostgresMigrations</code></td><td>shipping and running migrations, local or remote-connstring</td></tr>
<tr><td><code>PostgresBackup</code></td><td>periodic <code>pg_dump</code> backups: the script, the schedule, and a node that notices when no recent dump exists</td></tr>
<tr><td><code>PostgresPair</code></td><td>two machines, one Postgres cluster, and a <em>declared</em> primary: switchover, operator-decided failover, <code>pg_rewind</code> rejoins, and pgbouncer routing that follows — see [<code>resources/postgres-pair.md</code>](/docs-postgres-pair.html)</td></tr>
<tr><td><code>PostgresTemplate</code></td><td>template databases: build once, lock, hand out clones (<code>salmon-migrator config template</code>/<code>clone</code>)</td></tr>
<tr><td><code>PostgresTls</code></td><td>Postgres authenticating clients by certificate, and the material that makes it possible</td></tr>
<tr><td><code>Postgrest</code></td><td>PostgREST service configuration</td></tr>
<tr><td><code>WireGuardVpn</code></td><td>a full static-server/dynamic-client WireGuard VPN, transport-agnostic on key exchange</td></tr>
<tr><td><code>Gcp.CloudRunDeploy</code></td><td>build a podman image, push it to Artifact Registry, deploy it to Cloud Run</td></tr>
<tr><td><code>Gcp.PostgrestCloudRun</code></td><td>PostgREST on Cloud Run talking to a Postgres elsewhere over a client certificate</td></tr>
<tr><td><code>Gcp.PreviewEnvironment</code></td><td>several Cloud Run deploys composed into one named node: a preview environment</td></tr>
<tr><td><code>Gcp.VmProvision</code></td><td>turn up a GCE instance, then run a salmon binary on it over SSH via <code>Self</code></td></tr>
</table>
```

`salmon-ops-recipes-experimental` (not part of the default package set — see [Build](#build )) holds `SreBox.CertSigning` (certificate signing workflows), `SreBox.KitchenSinkBlog`, `SreBox.KitchenSinkMultiSites`, `SreBox.GeneratedSite`, and the `Salmon.Builtin.Nodes.Acme` builtin (ACME/Let's Encrypt certificate issuance).

## Binaries

`salmon-apps/` — each one is a small `Main` over a recipe:

```html
<table>
<tr><th>Binary</th><th>Does</th></tr>
<tr><td><code>salmon-migrator</code></td><td>Postgres migrations, template databases and clones (<code>config template</code>/<code>clone</code>)</td></tr>
<tr><td><code>salmon-pgpair</code></td><td>a Postgres primary/standby pair whose primary is a declaration — see [<code>resources/postgres-pair.md</code>](/docs-postgres-pair.html)</td></tr>
<tr><td><code>salmon-pg-backup</code></td><td>take a Postgres dump now, or install the cron job that keeps taking one, here or on another machine</td></tr>
<tr><td><code>salmon-init-locally</code></td><td>the local-machine salmon setup (sudoers, the salmon user and group)</td></tr>
<tr><td><code>salmon-gcp-toy</code></td><td>a tiered, throwaway exercise of the GCP builtins against a real project — see [<code>resources/gcp-toy-validation.md</code>](/docs-gcp-toy-validation.html)</td></tr>
<tr><td><code>salmon-toy-qemu-pg-ha</code></td><td>the <code>salmon-pgpair</code> demo on three qemu guests, with a client that keeps writing while the primary moves</td></tr>
<tr><td><code>salmon-fleet</code></td><td>the controller's side of pull mode: <code>status DIR</code> folds the hosts' status documents into one line per host; <code>keygen</code>/<code>sign</code> make signed documents</td></tr>
<tr><td><code>salmon-tui</code></td><td>a terminal client for <code>run serve --http</code> (or <code>--http-tcp</code>)</td></tr>
</table>
```
